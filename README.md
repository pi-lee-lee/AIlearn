# AILearn

머신러닝 교재(`머신러닝.pdf`)를 따라가며 작성한 연습 스크립트 모음. 각 파일은 다른 파일에
의존하지 않는 독립 실행 스크립트이고, 앞 파일의 코드를 일부 다시 쓰더라도 그대로 복사해
자족적으로 둔다.

## 실행

```bash
.venv/bin/python test3.py
```

데이터셋은 매 실행마다 네트워크에서 내려받는다(로컬 캐시 없음). 오프라인에서는 동작하지 않는다.

| | 사과 | 파인애플 | 바나나 |
|---|---|---|---|
| 평균 이미지 거리 (`test7.py`, 정답 사용) | 100 | 97 | 98 |
| k-평균 (`test8.py`, 정답 미사용) | 90 | 100 | 98 |

k-평균은 정답을 전혀 안 쓰고도 288/300을 제자리에 넣었다. 이너셔 감소폭이 k=2→3 에서
7.8억, 3→4 에서 4.2억으로 꺾이므로 엘보우도 실제 과일 종류 수인 3을 가리킨다. 다만 실루엣
점수는 k=2 를 가리킨다(0.393 vs 0.242) — 사과와 파인애플이 닮아 둘을 합치는 편이 더 잘 뭉쳐
보이기 때문. 지표가 엇갈리는 것이 일반적이고 최종 판단은 사람이 한다.

### PCA 로 차원을 줄인 뒤 (`test9.py`)

로지스틱 회귀 5-폴드 교차 검증(전체 300장). 특성 수를 줄여도 정확도가 유지된다.

| 특성 수 | 설명된 분산 | 교차 검증 | 폴드당 학습(초) |
|---|---|---|---|
| 10000 (원본) | — | 0.9967 | 0.084 |
| 50 | 0.9215 | 0.9967 | 0.004 |
| 2 | 0.5 | 0.9967 | 0.009 |

10000개를 2개로 줄여도 점수가 같다 = 픽셀 대부분이 중복 정보였다는 뜻.

PCA 자체도 0.079초가 든다. 모델을 한 번만 학습하면 본전이지만, 교차 검증·그리드 서치처럼
반복 학습하면 이득이 커진다(5-폴드 기준 0.426초 → 0.098초).

두 파일이 짝을 이룬다.

- `test9.py` — `train_test_split` 후 **훈련 세트로만 `pca.fit`**, 테스트에는 `transform` 만
  적용(스케일러와 같은 원칙). 방법론은 올바르나 테스트가 60장뿐이라 세 조건 모두 1.0 으로
  뭉개져 변별력이 없다.
- `test9-1.py` — 분리 없이 300장 전체를 교차 검증. 방법론은 느슨하지만 위 표의 0.9967 처럼
  비교 가능한 숫자가 나온다.

위 결과표는 `test9-1.py` 기준이다.

## 딥러닝 — Fashion MNIST

Keras 와 PyTorch 를 같은 파일명으로 나란히 구현한다. `deep_ke/` 와 `deep_to/` 에 같은 이름의
파일이 있고 같은 결과를 내야 한다. TensorFlow 는 Python 3.14 빌드가 없어 Keras 3 를
**PyTorch 백엔드**로 돌린다(`KERAS_BACKEND=torch`, keras import 전에 지정).

| 파일 | 내용 |
|---|---|
| `deep_ke/test10.py`, `deep_to/test10.py` | 인공 신경망. 밀집층 1개(784→10), 5 에포크 |
| `deep_ke/test10-1.py` | 같은 문제를 `SGDClassifier` 로. 신경망을 쓰기 전 기준선(짝 없음) |
| `deep_ke/test11.py`, `deep_to/test11.py` | 심층 신경망. 은닉층 100개 + relu, SGD 와 Adam 비교 |
| `deep_ke/test12.py`, `deep_to/test12.py` | 검증 손실로 과대적합 시점 찾기, 드롭아웃, 조기 종료 |
| `deep_ke/test13.py`, `deep_to/test13.py` | 합성곱 신경망. 패딩·스트라이드·풀링, 특성 맵 크기와 파라미터 수 |

| | Keras | PyTorch |
|---|---|---|
| 파라미터 | 7,850 | 7,850 |
| 검증 정확도 | 0.8241 | 0.8272 |
| 에포크당 학습 | 6.6초 | **0.4초** |

정확도 차이 0.003 은 두 프레임워크의 가중치 초기화 방식이 달라서 생긴다. 시드를 맞춰도 사라지지
않으므로 한쪽을 튜닝해 맞추지 않는다.

속도 차이 16배는 배치당 약 4ms 다(배치 1500개 x 4ms = 6초). 이 4ms 의 대부분은 **프레임워크가
아니라 장치 차이**다. Keras 3 의 torch 백엔드는 MPS 가 보이면 자동으로 쓰고
(`keras/src/backend/torch/core.py` 의 `DEFAULT_DEVICE`), `deep_to/` 스크립트는 CPU 에 그대로
둔다. 같은 모델·같은 배치 크기로 장치만 바꿔 재면 이렇게 갈린다.

| 에포크당 (배치 1500개) | CPU | MPS |
|---|---|---|
| Keras | 1.5초 | 6.7초 |
| PyTorch | **0.3초** | 0.8초 |

- **MPS 왕복이 배치당 약 3.5ms**(6.7 − 1.5초). 격차의 80% 가 여기서 나온다.
- **Keras 자체 오버헤드는 배치당 약 0.8ms**(1.5 − 0.3초). numpy→텐서 변환, 메트릭 누적,
  콜백 몫이고 나머지 20% 다.

PyTorch 도 MPS 로 옮기면 0.3초에서 0.8초로 느려진다. 784x10 행렬 곱은 순식간에 끝나서 GPU 로
보내고 받는 비용이 연산량보다 크기 때문이다. **모델이 작을수록 장치 이동이 손해다** — 지금이
최악의 조건이고, `test13.py` 의 합성곱처럼 연산량이 커지면 관계가 뒤집힌다.

Keras 를 CPU 로 고정해 재보려면 `KERAS_TORCH_DEVICE=cpu` 를 지정하고 실행한다.

### 은닉층과 옵티마이저 (`test11.py`)

은닉층 100개 + relu 를 넣고 5 에포크. 같은 구조에 옵티마이저만 바꿔 비교한다.

| | Keras | PyTorch |
|---|---|---|
| 파라미터 | 79,510 | 79,510 |
| SGD 검증 정확도 | 0.8446 | 0.8277 |
| Adam 검증 정확도 | **0.8781** | **0.8722** |

**Adam 이 SGD 를 3~4%p 앞선다.** SGD 는 79,510개 파라미터 전부에 같은 보폭(`lr`)을 쓰는데,
기울기가 작은 파라미터는 사실상 움직이지 않는다. Adam 은 기울기 제곱의 평균으로 나눠 크기를
지우고 방향만 남기므로 파라미터마다 제 속도로 나아간다. Adam 의 첫 에포크가 SGD 의 5 에포크에
근접한다.

`test11.py` 의 SGD 는 모멘텀이 없는 맨몸이다. 실무의 SGD 는 `momentum=0.9` 를 붙이므로
이 격차는 실제보다 크게 보인다.

프레임워크 간 차이가 `test10.py` 의 0.003 보다 크다(SGD 0.017, Adam 0.006). 층이 늘어
초기화 차이가 누적될 지점이 많아졌기 때문이고, 한쪽을 튜닝해 맞추지 않는다.

### 과대적합과 드롭아웃 (`test12.py`)

Adam, 은닉층 100개, 20 에포크. 훈련 손실만 보면 20 에포크 내내 계속 내려가서 언제 멈출지
알 수 없다. 검증 손실을 함께 재야 과대적합 시점이 보인다.

| | Keras | PyTorch |
|---|---|---|
| 드롭아웃 0.0 — 최저 검증 손실 | 0.3181 (13에포크) | 0.3157 (13에포크) |
| 드롭아웃 0.0 — 마지막 검증 손실 | 0.3442 | 0.3532 |
| 드롭아웃 0.2 — 최저 검증 손실 | **0.3118** (12에포크) | **0.3133** (13에포크) |
| 드롭아웃 0.2 — 마지막 검증 정확도 | 0.8823 | 0.8878 |
| 전체 실행 시간 | 8분 10초 | **64초** |

드롭아웃이 훈련-검증 격차를 절반 이하로 줄인다(PyTorch 기준 0.161 → 0.072). 훈련 손실은
오히려 높아지는데, 훈련 중에 뉴런을 꺼서 일부러 어렵게 만들기 때문이고 그게 정상이다.

**조기 종료 결과는 두 프레임워크가 크게 갈렸다.** Keras 는 10 에포크에 멈춰 8 을 복원했고
(0.3276), PyTorch 는 15 에포크에 멈춰 13 을 복원했다(0.3133). 검증 손실 곡선이 매끄럽지
않아 `patience=2` 로는 요철에 걸려 멈추기 때문이다. Keras 쪽 곡선을 보면 8 에포크 뒤 9, 10 이
연속으로 나빠져 중단됐는데 11 에포크가 더 좋았다. **교재의 `patience=2` 는 짧다** — 실무에서
5~10 을 쓰는 이유가 이것이고, 한쪽을 튜닝해 맞추지 않고 그대로 둔다.

`test12.py` 는 이 저장소에서 가장 무거운 스크립트다. Keras 쪽이 8분 걸리므로 다른 파일과 달리
긴 타임아웃이 필요하다.

### 합성곱 신경망 (`test13.py`)

이미지를 펼치지 않고 (28, 28, 1) 모양 그대로 넣는다. `Conv2D(32)` → `MaxPooling2D(2)` →
`Conv2D(64)` → `MaxPooling2D(2)` → `Flatten` → `Dense(100)` → `Dropout(0.4)` → `Dense(10)`.
옵티마이저와 조기 종료 조건(`patience=2`, `restore_best_weights`)은 `test12.py` 와 같고
모델 구조만 바뀌었다. `test12.py` 다음으로 무거워 3분 안팎이 걸린다.

| | Keras | PyTorch |
|---|---|---|
| 파라미터 | 333,526 | 333,526 |
| 되돌린 최적 에포크 | 6 (8에포크에 중단) | 8 (10에포크에 중단) |
| 최저 검증 손실 | **0.2180** | **0.2298** |
| 검증 정확도 | **0.9178** | **0.9163** |
| 에포크당 학습 + 검증 | 21초 | 19초 |
| 전체 실행 시간 | 2분 48초 (8에포크) | 3분 11초 (10에포크) |

`test12.py` 의 밀집층 모델(검증 손실 0.3118 / 0.3133, 정확도 0.8823 / 0.8878)보다 손실이
0.09 낮고 정확도가 3%p 넘게 오른다. 데이터도 옵티마이저도 같고, 784개로 펼치는 대신 28x28
모양을 남긴 것이 유일한 차이다.

**합성곱 층은 파라미터가 적지만 모델 전체는 그렇지 않다.** 커널 한 벌을 이미지 전체에
돌려쓰므로 합성곱 층은 입력 크기와 무관하게 2개 합쳐 18,816개다. 그런데 펼친 뒤의 밀집층
2개가 314,710개로 전체의 94%를 차지한다. 총 333,526개는 밀집층만 쓴 `test11.py`(79,510개)보다
오히려 많다.

**여기서 처음으로 Keras 가 PyTorch 보다 빨랐다.** 다만 에포크당으로는 21초 대 19초로 사실상
같고, Keras 쪽이 조기 종료로 2 에포크 덜 돌아 총 시간이 짧아진 것이다 — 전체 실행 시간 열은
두 프레임워크가 서로 다른 양의 일을 한 결과라 그대로 비교하면 안 된다.

에포크당 시간이 뒤집힌 원인은 장치다 — Keras 는 MPS, `deep_to/` 는 CPU 다(`test10.py` 절 참고).
밀집층만 쓸 때는 배치마다 MPS 로 오가는 비용이 연산량보다 커서 Keras 가 손해였는데, 합성곱은
연산량이 커서 그 비용을 넘어섰다.

## 실험 결과 — wine 데이터

`test_size=0.2, random_state=42`, 5-폴드 `cross_validate` 기본값, 모든 모델 동일 조건에서 측정.
그래디언트 부스팅만 `n_estimators=500, learning_rate=0.2`(나머지는 기본값).

결정 트리 테스트 점수는 `test2.py`가 출력하는 값(스케일링한 데이터로 학습)이다. 같은 트리를
스케일링 없이 학습하면 0.8585로, 사실상 차이가 없다. 트리 계열에 스케일링이 무의미하다는
근거가 이 두 숫자다.

| 모델 | 교차 검증 | 훈련 | 테스트 | 폴드당 학습(초) |
|---|---|---|---|---|
| 결정 트리 | 0.8555 | 0.9969 | 0.8592 | 0.012 |
| 랜덤 포레스트 | **0.8903** | 0.9969 | **0.8908** | 0.137 |
| 엑스트라 트리 | 0.8888 | 0.9969 | 0.8862 | 0.103 |
| 그래디언트 부스팅 | 0.8780 | 0.9382 | 0.8708 | 0.872 |
| 히스토그램 부스팅 | 0.8794 | 0.9255 | 0.8669 | **0.075** |

읽을 거리:

- **앙상블은 단일 트리를 확실히 이긴다.** 0.8592 → 0.89 근처. 다만 랜덤 포레스트에서 이미
  한계에 닿았고, 그 위로는 모델을 바꿔도 더 오르지 않는다. 특성이 3개뿐이라 짜낼 여지가 없다.
- **교재 설명과 달리 이 데이터에서는 부스팅이 랜덤 포레스트에 진다.** 부스팅 계열은 특성이
  수십~수백 개인 정형 데이터에서 강점이 나오는데 여기는 그 조건이 아니다.
- **부스팅 계열만 훈련 점수가 낮다**(0.93~0.94 vs 1.00 근처). 얕은 트리를 쓰기 때문이고,
  훈련-테스트 격차가 가장 작다 = 과대적합에 강하다.
- **히스토그램 부스팅이 일반 부스팅보다 11배 빠르면서 점수는 더 높다.** 분할 후보를 256개
  구간으로 고정하기 때문. 데이터가 커질수록 이 격차가 벌어진다.

## 파일 이름에 관한 메모

번호는 작성 순서라 교재 진도 순이 아니다. `test2.py`(결정 트리) 다음 진도가 `test02*.py`
(교차 검증)이고, `test3.py`부터 다시 앙상블로 이어진다. 위 학습 진행 표가 실제 순서다.

`test02-1.py`처럼 하이픈이 든 이름은 `import` 할 수 없다. 지금은 전부 단독 실행 스크립트라
문제없지만, 다른 파일에서 가져다 쓸 일이 생기면 밑줄(`test02_1.py`)로 바꿔야 한다.
